### 限定実ファイルのDesktop確認（新経路・未実施）

1. 稼働確認済みdevの `dev.html?mode=project-scene&storage=validation` を開く。
   「プロジェクト名」を入力し「3Dモデルとメディアを選択」で静的GLBとPNGを選び、
   「プロジェクトを作成」。選んだ形状・元の色／テクスチャが表示されることを確認。
   今回の入口は合計64 MiBまで。これは検査の打切り上限で、容量・速度の保証ではない。
2. Shift＋左クリック（またはピン追加）で不透明な面に置き、位置を確認して確定。
   本文・タイトルを編集し、「メディアを追加」で新しいPNGを選択して添付。
   作成時に選択したPNGの再利用は「登録済みメディア」から選んで添付する。
   右のキャプション一覧に「メディア 1」が出ることを確認。同じ画像をもう一度添付すると
   「メディア 2」、添付を一つ確認付きで削除すると「メディア 1」に戻る。他の記録は変わらない。
   2件目も作り、連続選択で各ウィンドウと添付画像を確認。
3. 本文を未確定のまま「プロジェクトを選ぶ」を押す。切替が拒否され、入力が残ることを確認。
   入力を確定または取り消し、一覧へ戻る。同じ名前のProjectを「開く」で再開し、
   ピン位置・文言・PNG・一覧の添付件数を確認。ページ再読み込み後も同じ内容を確認。
4. 「モデル」タブの「3Dモデルを追加」で静的GLBを一つ選択。現在シーンに新しいモデルが
   表示され、既存のモデル・記録・視点が保持されることを確認。同じファイルをもう一度
   追加した場合も別モデルになる。追加した対象を選び「モデルの配置を編集」。移動・回転・均等拡縮を試し、
   モデルとピンが一緒に動くこと、取消で元に戻ることを確認。確定後に再開し配置を確認。
   配置は全シーン共通、回転・拡縮の中心はモデルの原点。個々のピンの元座標は変更しない。
   ピンを付けたモデルを一覧で選び「隠す」。モデルとその3Dピン・接続線だけが消え、
   カメラ、一覧の記録、開いた本文ウィンドウは残ることを確認。非表示モデルの配置編集は不可。
   「キャプション」タブの該当記録から「モデルを表示」で戻せることを確認する。
   「モデル」タブへ戻り「このモデルだけ表示」→「全体表示」で見えているモデルに寄り、
   「すべて表示」で解除。hide/showだけではカメラが動かず、「このシーンに表示」のチェックも変わらない。
   一時非表示はScene別。別Sceneへ移って戻れば保持、Projectを再開すると解除される。
   閲覧専用タブでも一時表示操作は使えるが、シーンへの登録変更はできない。
5. 「マテリアル」タブでモデルと「面」を選び、「適用範囲」を確認して「設定を編集」。
   不透明・照明あり・片面の元材質で「照明」と「表示する面」を変更し「変更を適用」。
   対象材質だけが変わり、他のモデル・テクスチャ・ピン位置が保たれることを確認。
   「この範囲の設定を解除」→「設定を解除する」で共通設定または元材質へ戻ること、
   保存・再開でも設定が保たれることを確認。「指定した色を透過」を「有効」にし、
   「透過する色」「色の許容範囲」を指定して適用。抜けた部分ではなく、その背後にある対象モデルの面にピンを置けること、
   面がなければ置けないことを確認。手前の別モデルが不透明なら、その奥には置けない。
   背後の面を自動で同じ対象と推測する機能ではない。ピン移動は元のモデル内だけで行う。
   対象外材質は変わらず、解除・再開でも結果が一致することを確認。
   ぼかし・不透明度など、この限定経路で未対応の欄は変更不可でよい。
6. 「視点」タブの「背景色」で色を選ぶ。「背景に適用」するまで3D表示は変わらないこと、
   適用してもカメラ・ピン位置が動かないことを確認。「標準色」は薄い灰茶色を入力する。
   「取り消す」→「変更を取り消す」なら現在の背景は変わらない。
   色を適用後「視点を作る」で名称を入力し「視点を追加」。Projectを再開し、
   「保存した視点」からその名称を選び「表示」でカメラと背景が戻ることを確認。
   背景の入力中はProject／Sceneの切替が拒否されることも確認する。
   背景の適用だけではファイルを保存したことにはならない。
7. 別の検証Projectを作り、一覧から両方を切り替える。記録・画像が混ざらないことを確認。
   失敗した場合は削除・再作成をせず、その画面をまとめて共有する。

PNG／静的GLBの後入れ、実GLB配置、材質の照明／表裏／hard色抜き／解除は限定接続済み。
GPU固有の追加確認は同じバッチにまとめる：テクスチャ・頂点色・UV1を使うモデル、縮小表示、
奇数ピクセル幅・表示倍率変更でも、色抜きと配置先が一致すること。判定不能の表示が出たら
配置は行わず、保存内容を保ったまま共有する。記録rendererのテストはこの実測の代わりではない。
他画像・モデル形式、半透明効果、元からMASK／BLEND材質の面へのpin配置は未接続。
普通のMeshや別の画像形式全体の合格ではない。iPhone／offline確認は
別途exact buildと承認済み経路を用意して行い、devサーバーを根拠にしない。

### 次の手動確認：新しい保存方式（一括して報告）

開発側がサーバーと依存配信を確認してから、チャットでも同じ手順を案内する。
既存の保存URLを置き換えず、新しいモードのURLを控える。実ファイルは使わない。

1. `dev.html?mode=project-scene`の「新しい保存方式を試す」を選択。
   「設備の確認箇所」のタイトルと本文を変更し、「変更を適用」。保存済みになり、
   再読み込み後も両方残る。「設備の確認」シーンでも同じ内容が見える。
2. 同じURLを別タブで開く。閲覧専用と表示され、タイトル・本文を編集できない。
   編集用タブで変更を保存し、閲覧用タブの「保存状態を確認」で変更が見える。
   編集用タブを閉じて閲覧用タブを再読み込みすると、編集できる。
3. シーン切替、検索、色絞込み、複数Captionウィンドウ、カメラ操作を確認。
   モデルの面をShift＋クリックし、ギズモで仮位置を動かして取り消す。
   ピンが増えていないことを確認後、もう一度追加して確定し、タイトル・色を変更。
   追加したピンを選び「位置を調整」で調整・確定し、再読み込み後も位置と色が残る。
4. 別のシーンの「キャプションの追加・除外」で、そのCaptionを選び追加する。
   同じ選択で「このシーンから外す」。現在のシーンからだけ消え、元のシーンでは
   本文・位置・色が残る。再追加後も同じCaptionが一件だけ表示される。
   「モデル」タブでもシーンから除外／再追加し、Caption自体は消えないことを確認。
   再読み込みで所属が残る。未適用の本文を残して再読み込みすると離脱確認が出る。
5. 「視点」タブで「視点を作る」を選び、名前を付けて「視点を追加」。
   カメラを動かした後、保存した視点を選んで「表示」すると元の表示へ戻る。
   「編集」から名前の変更と「現在の表示を使用」を適用し、再読み込み後も残る。
   視点をもう一つ作り、「その他の操作」の「前へ／後へ」で順序を変更する。
   「開始時の設定」を適用しただけでは表示は動かず、別シーンから戻ると適用される。
   開始時の指定を解除してから「削除」→「削除する」で一件だけ消し、再読み込みでも
   残りの視点が保持される。閲覧専用タブでは「表示」はできるが保存・設定変更はできない。

## 1. 最初に説明する製品状態

LociViewは、3Dデータを見て、空間上へCaptionを記録し、そのProjectを
やり取りするためのlocal-first／offline対応workspaceである。次セッションは
UIを触る前に、以下を自身の平易な日本語で説明する。

- LociView Native Projectが、閲覧、編集、保存、交換を行う作業用の正本。
- LociMyu ZIPは、別のNative Projectを作るためのread-only互換入力。
  legacy LociView v1も、安全なopen／viewと非破壊Native変換のための互換入力。
  どちらの原本にも書き戻さない。
- 初回public candidateで書込み可能なのはNative Projectだけ。
- Nativeを正本にするのは、受入れ済みの複数Asset、Caption、DisplaySet、保存・交換を
  一つの検証済みdata modelで更新しながら、互換原本のbytesと意味を変えないため。
- ユーザーが選択・表示・編集する単位はAsset。Mesh、通常Point、Gaussian
  Splatting（GS）はRepresentation形式。Projectには互いに独立した複数Assetを
  置けて、Assetごとに選択、表示／非表示、位置、回転、uniform scaleを持つ。
  MeshとGSが同じ対象や同じ範囲を表す必要はない。
- Interaction Proxyは対応するGS Assetの操作を助けるもの。別の論理Assetや
  layerとして通常ユーザーへ見せない。

表示・記録に関する次の役割を混同しない。

| 概念 | 利用者にとっての役割 |
|---|---|
| Caption | 対象Assetへtitle／body／colorと任意のmediaを記録する |
| 3D配置／gizmo | Captionを対象Assetの空間へ置き、位置を調整する |
| 添付メディア | Captionに属する記録を追加・確認する |
| DisplaySet | Caption群、material appearance、任意の既定Saved Viewを一緒に切り替える |
| material appearance | DisplaySet内で対応するMesh Assetのmaterialの見え方を変える |
| Saved View | camera／view状態を呼び戻し、任意でDisplaySetの既定にする |
| Asset visibility | Assetを個別に表示／非表示にする |

DisplaySetはvisibility、layer hierarchy、Asset groupの別名ではない。labelや
navigationでも一つの概念へ潰さない。

4種類のpackage出力も目的が異なる。

| 出力 | 目的 |
|---|---|
| 完全バックアップ | 同じ完全なProjectを復元する |
| 共同編集用package | 同じProject lineageへ対応変更をmergeする |
| 閲覧共有用package | merge不能なcopyを原則View modeで開く |
| 編集用コピー | 新しいidentity／lineageの独立した編集用Projectを始める |

filenameを変えてもpackageの目的は変わらず、目的の証明にもならない。検証済みの
package内容から判定し、結果を利用者へ説明する。

candidateのmedia境界は次のとおり。

- Native Caption添付はPNG、JPEG、WebP、GIFに対応済み。
- HEIC／HEIFは端末上で別のJPEGを書き出して添付する承認済みフローを使う。
  original-byte HEICはcandidate後の必須開発。
- 動画と音声もcandidate後の必須開発で、candidate機能ではない。
- 製品概念と表示名は`添付メディア`。candidateで利用できる追加操作は画像だけで、

## 8. 操作量と判断量の測定

各taskで、開始地点、目に入る主要action、完了の合図、click／tap数、file dialog数、
screen／panel移動、mode切替、同じ情報の再入力、drag／gizmo前の準備、undo／retry、
大まかな所要時間を記録する。click数が少なければ常に良いとは扱わず、一つのactionへ
無関係な危険な意味を詰め込まない。

判断は、総数、不明瞭な選択、技術知識が必要な選択、安全な既定値で処理できる選択、
destructive／irreversible、source authority、conflict、画面から結果を予測できない
選択を記録し、(1) 利用者が決める、(2) 安全な既定値で自動化、(3) 通常は隠して
必要時だけ段階表示、の三つに分類する。

判断削減のために、source relation推測、conflict winner自動選択、無確認の破壊操作、
filenameによるpackage purpose推測、failure／unsaved stateの隠蔽を行わない。

## 9. 確認するUX原則

- 各screenに明確な主要actionを一つ置き、technical acceptance controlを隠す。
- 普通のtask languageを使い、重複入口と再入力を減らす。
- 安全な既定値とprogressive disclosureを使う。
- system state、save state、選択対象を見せる。
- 操作前に結果を予測でき、失敗時は次の安全な行動を示す。
- Desktop／iPhoneで概念と用語を揃え、mobileを単なる縮小Desktopにしない。
- keyboard／mouseとtouchの双方で主要taskを完遂する。
- LociMyu経験者と初見ユーザー双方のmental modelを試す。
