# 01. ビジョンと要件定義

LociView — ローカルファーストの3Dキャプションビューア（LociMyu後継）

## 1. 背景：LociMyuの到達点と限界

LociMyu αは「Google Drive上のGLBをブラウザで表示し、ピン+キャプションをGoogle Sheetsに保存する」ビューアとして機能している。UI/UX（3Dステージ + Caption/Material/Viewsタブ、Shift+Clickピン打ち、ピン色フィルタ、ビュープリセット）は実運用で練られており、これは資産である。

一方で構造監査（`Locimyu2/tasks/locimyu-public-release-review.md`）で以下が確認されている。

| 問題 | 内容 |
|---|---|
| ネット必須 | 認証・モデル・画像・セーブの全てがGoogle API依存。オフラインでは何もできない |
| 同時編集破壊 | キャプション更新がシートの行番号ベースで、複数人編集時に他人の行を上書きし得る（P0） |
| ID設計の欠如 | プロジェクトはシート名検索で特定、画像はDrive fileId直接参照、マテリアル設定は表示名キー。すべて不安定 |
| OAuth審査の壁 | `drive.readonly` はrestricted scope。一般公開にはCASA等の審査コストが恒常的に発生し得る |
| 配布構造 | 49ファイルのパッチ集積、Three.jsをCDNから実行時取得、ビルドシステムなし |

LociViewはこれらを「パッチで直す」のではなく、**データの置き場所と形を変えることで根本から解消する**。Google APIを切り離せば、P0の同時編集問題・OAuth審査・ネット必須は同時に消える。

## 2. ビジョン

> **ネット環境がない場所でも、3DCGを使った記録を残せること。**
> **そして複数人の記録を、労少なく統合できること。**

- 現場（屋外・地下・遠隔地・電波のない場所）で、3Dモデル/点群にキャプションを打ちながら記録する
- 記録は1つのファイル（ZIPパッケージ）として持ち運べる。メール・Drive・LINE・USBメモリ、手段を問わない
- 別々の人が別々の場所で付けたキャプションを、開くだけで統合できる（git的マージ）
- PCでもスマホでもタブレットでも、同じHTMLアプリで開ける

### 設計原則

1. **Local-first**: ネットは「あれば便利」であり前提ではない。全機能がオフラインで完結する
2. **File as truth**: サーバもDBもない。プロジェクト=1個のZIPファイル。ユーザーがデータを完全に所有する
3. **Merge by design**: セーブデータは最初から統合されることを前提に設計する（後述のop-log方式）
4. **Preserve originals**: 取り込んだ3Dモデル・画像の原本は改変しない。設定・注釈は常に別レイヤーに持つ（記録用途では原本性が重要）
5. **Inherit the UX**: LociMyuで練られたビューイングUIは概ね維持する
6. **Barrier-free data**: セーブデータの中身は、専用ソフトなしで確認・編集できる経路を常に保つ。スプレッドシート（Google Sheets / Excel）で開いて読める・直せる・座標をコピペできることを、機能ではなく設計の前提とする

## 3. 想定ユースケース

- **UC1 単独記録**: 1人がPCでモデルを読み込み、ピン+キャプションを付け、ZIPで保存する
- **UC2 回覧統合**: プロジェクトZIPを複数人に配布。各自がオフラインで加筆した複数のZIPを、1人が順に取り込んで統合版を作る
- **UC3 現場閲覧・追記（スマホ）**: DriveやLINEで受け取ったZIPをスマホで開き、現場で確認しながら追記し、共有シートで送り返す
- **UC4 スプレッドシート運用**: キャプション一覧をスプレッドシートで一括編集・レビューし、再取り込みする（Google Drive中心の既存運用の継続）
- **UC5 LociMyu資産の移行**: 既存のLociMyuセーブ（Sheets）+Driveフォルダの内容をLociViewプロジェクトに変換する

## 4. 機能要件

### 必須（MVP）

- FR-01: プロジェクトZIPのドラッグ&ドロップ / ファイル選択で起動する
- FR-02: Google DriveのフォルダZIPダウンロード（xlsx化されたシート+画像+モデル）をインポートウィザードで取り込める
- FR-03: GLB / OBJ(+MTL) / STL / PLY（メッシュ・点群とも基本表示）の表示
- FR-04: ピン打ち（クリック/タップ）、キャプション（タイトル・本文・色・添付複数）、ピン色フィルタ — LociMyu同等
  - 添付はassetの汎用参照（`attachments`）とし、データ構造上は画像・映像・音声を最初から区別なく扱える。MVPのUIは画像のみ（映像UIはFR-31、音声は予約のみ）
- FR-05: マテリアル調整（不透明度・両面・unlit・クロマキー） — LociMyu同等
- FR-06: ビュープリセット・平行投影・6方向カメラ・背景色 — LociMyu同等
- FR-07: 編集ユーザーの固有ID（初回起動時に自己発行、表示名付き）と、全キャプション・全編集操作への固有ID付与
- FR-08: 別ZIPの取り込みによるマージ（同一プロジェクトIDの統合）。差分表示（追加/更新/競合）
- FR-09: プロジェクトのZIPエクスポート（PCでは上書き保存、スマホでは共有シート/ダウンロード）
- FR-10: ブラウザ内ワークスペースへの自動保存（作業中データの喪失防止）
- FR-11: キャプション一覧のCSV/xlsxエクスポート・インポート（スプレッドシート往復運用）
  - Excelで文字化けしないUTF-8 BOM付きCSV、座標は完全精度で出力
  - エクスポートZIPに閲覧用 `captions.csv` を常に同梱（LociViewが無くても解凍すれば中身が読める）
  - `modelName` 列の書き換えでキャプションのモデル一括付け替えが可能（モデル入れ替え時の座標コピペ運用を支える）
- FR-12: PWAとしてオフライン起動
- FR-13: **表示セット** — キャプション群・マテリアル設定・ビューを束ねた名前付きセットを複数持ち、切り替えられる（LociMyuのシート切替の継承。半透明表示用セット/Unlit表示用セットのように「見え方に応じたキャプション表示」を実現する実運用があるため必須）
- FR-14: **Undo/Redo** — 直近操作の取り消し/やり直し。逆向きopの追記として実装し、履歴・マージ安全性を保つ（スマホのタップ誤操作対策として必須）
- FR-15: **キャプション検索・絞り込み** — タイトル/本文の全文検索、タグ・編集者・日付・色での絞り込み（移行時点で約200件が存在するため初日から必要）

### 拡張（Phase 2以降）

- FR-20: FBX表示
- FR-21: 点群の拡張（PCD対応、点群向け調整UIの強化、自動サブサンプル。LAS/LAZは需要確認後）
- FR-22: 複数モデルの同時ロード / モデル差し替えとピンの追従
- FR-23: 大規模点群のLOD表示
- FR-24: 競合の手動解決UI（自動解決の上書き）
- FR-25: 任意のクラウド同期プロバイダ（Drive等）の再接続 — コアから分離したオプションとして
- FR-26: **その場カメラ撮影→添付** — ピン打ち→撮影→即添付の一連動作（スマホ、`input capture`、オフライン動作。Phase 2序盤）
- FR-27: **変更履歴ビュー** — キャプション別の変更年表、プロジェクトの時点表示（op-logからの導出のみで実装）
- FR-28: **画像・レポート書き出し** — 現在ビューのPNG保存（Phase 2）、ビュー画像+キャプション一覧の整形レポートHTML/PDF（Phase 3）
- FR-29: **自己完結ビューア書き出し** — プロジェクトを埋め込んだ閲覧専用HTML 1ファイルを生成。受領者はインストール不要でダブルクリック閲覧（納品物・長期保存の最終形）
- FR-30: **計測ツール** — 2点間距離の測定 + スケール校正（既知寸法の入力による倍率合わせ）。校正とセットで初めて意味を持つ
- FR-31: 映像添付の再生UI（データ構造はMVPから対応済み。ZIP容量への影響が大きいため取込時に警告とサイズ上限）
- FR-32: **表示セットの重ね合わせ表示** — 複数セットのピン・キャプションを同時表示する検証モード。主セット1つがマテリアル設定とビューを支配し、副セットはピンのみ提供（マテリアル競合を構造的に回避）。データ構造変更なしで実現できる純粋な表示機能
- FR-33: CSV手編集の自動検出 — 取込ZIP内の `captions.csv` がops由来の状態と食い違う場合、「CSVの手編集を反映しますか？」と提案（Phase 2）

## 5. 非機能要件

- NFR-01: オフラインで全機能が動作する（初回ロード後、ネット通信ゼロ）
- NFR-02: マージは決定的（同じ入力集合からは誰がどの順で統合しても同じ結果になる）
- NFR-03: セーブデータは人間可読（JSON/JSONL）。10年後にLociViewが無くてもデータが読める
- NFR-04: スマホ実用範囲: メッシュ数十万ポリゴン・点群〜数百万点・画像数百枚規模で操作可能
- NFR-05: 悪意あるZIP/モデルに対する防御（zip bomb、パストラバーサル、文字列注入 — 監査チェックリスト継承）
- NFR-06: 依存はビルド時に固定（lockfile）。実行時CDN依存ゼロ。厳格CSP
- NFR-07: スキーマバージョンを持ち、旧バージョンのプロジェクトを常に開ける（前方互換の努力、後方互換の保証）

## 6. 非目標（やらないこと）

- リアルタイム共同編集（同時に同じ画面を編集する機能）。統合は非同期マージで行う
- サーバサイドの構築・アカウントシステム。ユーザーIDは自己発行であり認証ではない
- 3Dモデルの編集機能（ジオメトリ加工・リトポ等）。あくまでビューア+注釈
- Google API連携のコア機能化（MVPではAPI連携ゼロ。将来もオプション扱い）
- E57等の業務系点群フォーマット完全対応（需要が確認されてから）

## 7. 成功基準

1. 機内モードのスマホで、受け取ったZIPを開いてピンを追記し、ZIPを送り返せる
2. 3人が別々に編集した同一プロジェクトの3つのZIPを、ドロップ3回で統合でき、キャプションの欠落・重複がない
3. LociMyuの既存ユーザーが、現行UIの知識のまま迷わず使える
