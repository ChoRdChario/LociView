### 表示セット切替（LociMyuのシート切替の継承）

実運用ヒアリングにより、シート切替は「マテリアルの透明度・Unlit等の見え方」と「その見え方に合わせたキャプション位置」を束ねる**見え方セット**として使われていることが確認された（半透明セットでは内部にピン、通常セットでは表面にピン、等）。よって:

- パネル最上部にセット選択ドロップダウン + 新規作成ボタンを置く（LociMyuの「Select sheet… + Create」と同位置・同作法）
- セット切替で、キャプション一覧・マテリアル設定・ビュープリセットが一括で切り替わり、セットの既定ビュー（または最後に保存したビュー）が適用される
- セットの改名・並び替え・削除はドロップダウン横のメニューから。削除は所属キャプションごとtombstone化（マージで復元可能）

## 3. 画面構成

### 3.1 ホーム（起動画面）

```
┌──────────────────────────────┐
│  LociView                     │
│  ┌────────────────────────┐  │
│  │  ZIPをここにドロップ        │  │  ← .lociview / Drive ZIP / モデル単体
│  │  （またはタップして選択）     │  │     すべてここ1つで受ける
│  └────────────────────────┘  │
│  最近のプロジェクト（ワークスペース内）│
│   ・○○遺構 実測記録   [開く][書き出し]│
│  [新規プロジェクト] [プロファイル]  │
└──────────────────────────────┘
```

- 投入物の自動判別（docs/02 §6.2）: lociview.json有り→開く or マージ確認 / 無し→インポートウィザード / モデル単体→新規プロジェクト作成
- **開いているプロジェクトがある状態でのZIP投入 = マージ**という一貫ルール

### 3.2 ビューア（メイン画面）

> `SUPERSEDED DRAFT`: 以下の4タブ/FAB案は採用前の案。現行はCaption / Material / Model / Views / Dataの5タブで、モバイルのピン追加は長押し、デスクトップはShift+Click。実挙動は`src/ui/viewerScreen.ts`を参照。

デスクトップ（>= 900px）: LociMyu同等の右パネル固定。
モバイル: 右パネルを**ボトムシート**化する。

```
┌────────────────┐
│                │  ← ステージ全面
│   3D stage     │
│                │
│  [◎ピン追加]      │  ← FAB(フローティングボタン)
├────────────────┤
│ ▔▔▔ (ハンドル)    │  ← 3段階スナップ: 折りたたみ(タブバーのみ)
│ Caption│Mat│Mdl│View│    半開き(リスト)・全開き(編集)
│  …パネル内容…     │
└────────────────┘
```

- タブは Caption / Material / **Model（新設）** / Views の4つ
- Modelタブ: モデル一覧（登記簿）、スケール/上軸/センタリング、点群サブサンプル率、統計表示
- Materialタブ: メッシュ選択時は従来UI、点群選択時は点サイズ・色モードUIに切り替え（docs/04 §6）

### 3.3 ピン追加のタッチ対応

> `SUPERSEDED DRAFT`: 以下のFAB方式は不採用。現行は長押しで追加し、通常タップは選択・操作に使う。

Shift+Clickはスマホに存在しないため:

- **ピン追加モード**トグル（FAB）: ONの間はタップ=ピン追加。追加後自動OFF（誤爆防止、連続追加は長押しでモード固定）
- デスクトップは従来のShift+Click併存
- タップ時のraycast半径はタッチ向けに拡大（docs/04 §6）

### 3.4 マージレポート画面

ZIP取り込み時に必ず表示:

```
統合結果 — 田中さんのデータ (2026-07-15 版)
 + 新規キャプション 12件
 ~ 更新 3件
 - 削除 1件
 ⚠ 競合の自動解決 2件
    「北壁の亀裂」body: あなたの7/14の変更が田中さんの7/15の変更で上書き
    [内容を見る] [自分の値に戻す]
                          [OK]
```

- 「自分の値に戻す」= 新しいopを積むだけ（履歴は消えない）。git的な難解さをユーザーに見せない
- レポートはキャプションリスト上のバッジ（新着/更新マーク）としても残す

### 3.5 書き出し/共有

- ヘッダの「書き出し」ボタン → プラットフォーム別に最適な動線（docs/06 §3）: 上書き保存（デスクトップChrome系）/ 共有シート（スマホ）/ ダウンロード（フォールバック）
- 書き出しオプション: フルパッケージ / **opsのみの軽量差分ZIP**（モデル・画像を除く。相手が原本を持っている回覧運用で通信量を激減させる。メール添付可能サイズ）

## 4. レスポンシブ・入力方針

- ブレークポイント1本（900px）でサイドパネル⇔ボトムシートを切替。中間デバイス（タブレット）は横置き=サイドパネル、縦置き=ボトムシート
- OrbitControls: タッチ1本=回転、2本=ピンチズーム+パン（three.js標準）。慣性ON
- キャプション本文編集はモバイルでは全開きシート+標準キーボード。ソフトキーボード出現時のビューポート縮小に`visualViewport`で追従
- すべてのタップターゲット44px以上

## 6. 状態表示・安心設計

- 保存状態インジケータ常時表示: 「ワークスペースに自動保存済み ✓ / 最終書き出し: 2時間前」— **「書き出していないデータがある」ことを常に可視化**（スマホのストレージ削除リスク対策、docs/06 §4）
- オフライン動作が正常系なのでオフラインバッジは出さない（ネットに繋がっても挙動が変わらない）
- 破壊的操作（キャプション削除・プロジェクト削除）のみ確認ダイアログ。削除はopなのでマージで復元可能な旨を添える
