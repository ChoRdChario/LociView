製品UI設計案：コンセンサス用モック

コア（データ層・ビューア）は実装・検証済みです。製品UIの実装前に、この案でレイアウトと操作の合意を取ります。 方針は docs/05 の通り「ビューイング体験はLociMyuを継承し、データ入出力まわりだけを置き換える」。 モック内の配色・部品はLociMyu αの実トーンをそのまま使っています。

継承右パネル+タブ構成、ピン色チップ、Shift+Clickピン、ダークトーン。既存ユーザーが迷わないこと。LociMyu α準拠
置換「GLB URL+Load」「Sign in」→ ZIPドロップ・プロファイル・書き出しメニューへ。ネット要素は消滅。
追加表示セット切替 / 検索 / Undo / Modelタブ / マージレポート / 保存状態の常時表示。

  • ＊「自分の値に戻す」は新しい編集を積むだけで履歴は消えない。gitの難解さ（conflict/rebase等の概念）はユーザーに一切見せない。新着・更新はリスト上の新着バッジとしても残る。

判断していただきたいこと

  1. Q1全体レイアウト：この継承方針（PC=右パネル、スマホ=ボトムシート3段階）でよいか。
    代替案はスマホでも常時分割（上下2分割固定）ですが、画面の狭さから非推奨です。
  2. Q2タブ構成：Caption / Material / Model / Views の4タブでよいか。
    Modelタブ新設が変更点。LociMyuの3タブに戻し、モデル調整を書き出しメニュー側に置く案もあります。
  3. Q3スマホのピン追加：FAB方式（タップ=1本、長押し=連続モード）でよいか。
    誤タップ防止として「追加後自動OFF」を既定にしています。常時ONが好みなら設定化します。
  4. Q4配色：LociMyuのダークトーン継承のみでよいか、屋外・現場向けにライトテーマも用意するか。
    直射日光下ではダークUIは視認性が落ちます。Phase 2でライトを足す前提なら、実装初期からトークン設計だけ両対応にしておきます（後付けより安い）。
  5. Q5書き出しメニューの並び：フルZIP / 差分ZIP（軽量） / CSV・xlsx / ビューPNG / 閲覧用HTML で過不足ないか。
    最頻出を1タップ目に置きます。現運用で最も多い書き出しはどれになりそうですか。
  6. Q6LociMyuから「これだけは変えるな」という操作・見た目が他にあれば教えてください。
    例：ピン色チップの並び、Materialタブのスライダー配置、Viewsの±XYZボタン等。指定がなければ現行準拠で実装します。
