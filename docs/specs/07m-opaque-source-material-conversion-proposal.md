# Existing opaque source-material conversion companion

Status: **APPROVED — grouped implementation ratified by PO 2026-10-28; bounded three-family workflow implemented and verified, not adopted.**
The PO approved the complete three-family workflow, new recipes/IDs and v1 absent-side
inheritance in one group. No per-family/helper approval is needed. This is the connected migration decision after05's existing Mesh source-edit
connection. It adds no renderer, dependency, public profile or general alpha policy.
[Todo](../../tasks/todo.md) owns current implementation/checks and sequencing.
Executed evidence covers the exact source/recipe subset below, typed editing,
five-purpose files/two returns, selected restore and cold reopen. Native has a

continuations. Physical iOS, offline/PWA, aggregate gates and release are not passed

## User outcome and decision

Convert an already supported Native, frozen-v1 or single-model LociMyu input whose
saved shading/face settings address an originally unlit or double-sided opaque
Mesh → inspect consequences → edit/reset the exact Scene/slot → five-purpose
files/two-way exchange → Review editable copy/Clean/restore/cold resume.

The new decision admits the four source combinations opaque/surface × lit/unlit
× front/double for addressed **visual Mesh** slots. Before this companion, converters accepted only
opaque/surface/lit/front. Saved opacity remains exactly1 and chroma remains disabled.
Keep the accepted original-source, exact-address and all-or-nothing rules. New
immutable recipes are required; changing the meaning of old recipes is prohibited.

This does not admit MASK/BLEND, fractional opacity, active chroma, Point/GS/Proxy
material editing, guessed owners/relations or an unlit→lit fallback. In particular,
old Native replaces factor opacity before source alpha testing, whereas the new
source MASK evaluator preserves the authored factor. A factor.4/cutoff.5 surface
can therefore change coverage even when saved opacity is1. Do not silently map it
to binary mask or claim that a source-semantic guard expansion solves that problem.

## Source and target contract

Use the exact current parsers, admitted profiles, real180→186 decode proof and
catalog/slot addresses. Changes are limited to addressed source-semantics admission
and the new v1 recipe's explicit absent-side inheritance rule below.
Unknown fields, missing/ambiguous mappings and unsupported active rows still reject
the entire conversion before publication. Unaddressed source slots keep their
current admission/display behavior; no unused slot creates a new recipe by itself.
For Native, effective addressed rows include every retained appearance checked by
07a/07k/07l, including hidden/noncurrent DisplaySets and retained revisions. Do not
limit admission or recipe selection to the currently visible Scene/model.

| Source family | Mapping and constraints retained |
|---|---|
| Native plain GLB |07a occurrence proof, exact materialSlotKey/representation/revision routing, one representation per affected family, existing identity-placement subset |
| Native mixed Point/GS/Proxy or07l Mesh |07k/07l source/body/frame rules, exact GLB occurrence or Mesh sourceAddress proof, existing dormant-history and source-family restrictions; adjustments target meshPrimary only |
| frozen-v1 |07i all-history typing, exact decoded producer key, unique base locator/selected occurrence, no name fallback or shared-material broadcast, tuple uniqueness and contradictory-alias refusal |
| LociMyu |07h one GLB, current valid row/authoritative Scene relation, exact material-name→distinct selected materialIndex fan-out, duplicate table/target refusal and existing inactive-row reporting |

For an addressed slot require exactly closed semantics:
`coverage={kind:'opaque'}, optics='surface', lighting='lit'|'unlit', doubleSided=boolean`.
Use the new domain capability after provider/content validation; do not duplicate
format registries or grant editability based on a supplied verified flag.

Target values retain the existing family-specific intent:

```text
opacity = 1
doubleSided = effective Native/LociMyu adjustment boolean;
              v1 present boolean, otherwise omit and inherit authored side
lighting = effective adjustment unlit ? 'unlit' : 'inherit'
compositing = {coverage:{policy:'inherit'},optics:'inherit'}
```

Native's side boolean is required; LociMyu's blank boolean keeps its existing false
meaning. For new v1 recipe7 only, an absent doubleSided field omits the target side
override and inherits the authored side, matching old context.ts/viewer reset
behavior. Old6's false default is frozen and remains equivalent on its front-only
subset. This explicit new mapping prevents an originally double-sided v1 material
from silently becoming front-only when no side adjustment was saved. Unaddressed
slots inherit their original side. False/absent unlit means inherit, including for an authored Basic source;
it never requests a new PBR material. Existing source PBR/Phong/Basic values,
texture/RGB/vertex contributions, coordinates and raw original bytes are retained.
Native keeps its existing disabled-chroma target values and quantization rules.
v1/LociMyu keep disabled chroma values only in original/private explanations under
07i/07h; this companion does not unify those distinct policies.

## Additive recipe selection and identity

Reserve these previously unused literals:

| Family | New recipe | Existing recipes kept exact |
|---|---|---|
| Native |`native-project-scene-recipe-9`|1–8|
| frozen-v1 |`v1-project-scene-migration-recipe-7`|1–6|
| LociMyu |`locimyu-project-scene-migration-recipe-5`|1–4|

Select the new recipe only if at least one **effective addressed** source slot is
opaque/unlit or opaque/double and all other applicable input conditions pass the
complete new subset. Inputs satisfying the old source subset retain their existing
recipe, IDs, report shape and recovery meaning. All-deleted v1 material history
keeps6; inactive/zero-match LociMyu rows do not select5. Detect this from complete
typed source/decode proof, before target IDs; do not catch an arbitrary old failure
and retry a broader parser, ignore a row or downgrade to an older recipe.

Native9 spans plain GLB,07k and07l **without using9 as a shape classifier**.
Determine the existing inspection/receipt lane from the verified original snapshot
and inspected source kinds at prepare and exact-source recovery: newMesh→07l lane,
otherwise non-Mesh/Proxy→07k lane, otherwise appearance GLB lane. Use that lane's
full body/ref/witness shape, source key grammar, origin storage and expected-record
checks. Recipe9 independently selects the new ID/acceptance domain.
All new9 initial records use the existing validation-initial-2/originRecipe9 marker
so a missing/mutated conversion receipt cannot downgrade to ordinary creation.
Update prepare, receipt allowlists, origin/appearance/JPEG/photo classification, startup/resume and
complete expected-record verification together. Never call the Mesh receipt reader
on a plain GLB receipt just because its recipe is9. Do not infer a lane from a
filename or unverified receipt-only hint. No new persisted discriminator is needed:
the exact verified original source already supplies the lane. Old1–8 jobs retain
their old dispatch and retry behavior. Preserve each lane's existing original/body/
Project capacity;9 alone grants no larger allocation or Desktop exception.
Receipt shape may select a candidate location and undergo provisional structural
checks before source inspection; it is never lane/publication authority. Raw GLB9
uses its existing whole-original capture once, then requires a verified plain-GLB
source lane before model/witness/publication work. CAS lanes inspect source metadata
through the verified Blob below. Do not add a preliminary whole-buffer read.
The source-lane check may hand its already verified immutable CAS Blob to the
same recovery invocation through a private one-use capability bound to FS/store/
exact ref. This only avoids the newly introduced duplicate CAS acquisition. Keep
the normal state/ack checks, original hash, witnesses and publication fences;
reselected user bytes still require CAS write and verified readback. No general
cache, cross-operation reuse or supplied verified flag is allowed.

Keep every existing source-key grammar and output prefix. Only the recipe domain
changes. In particular, Native override key is `['mesh-appearance',appearance.id]`,
v1 override key is `['material',sourceMaterialId]`, and LociMyu override key is
`['material-row','__LM_MATERIALS',row,sheetIdentity,modelPath,'gltfMaterial',index]`.
Their initial-event key remains `['initial-event','ovr',overrideSourceKey]`.

The UTF-8 preimage has no BOM, final LF or normalization:

```text
'lociview:'+recipe+':id:jcs-v1\n'
+ JSON.stringify([conversionId,sourceZipSha256,prefix,sourceKey])
```

LociMyu retains `workbookPath` between sourceZipSha256 and prefix. The escape is
one LF. Output ID is `prefix+'_'+sha256.slice(0,32)`; retain full digest/preimage,
reject shortened-ID/full-digest/entity collisions and sort mapping rows by target
ID. The [approved nine identity vectors](profiles/opaque-source-material-conversion.goldens.json)
fix two distinct overrides and one initial event per family, including literal
preimages, UTF-8 lengths and full SHA-256/shortened IDs. Independently review them
before implementation and keep all older goldens byte-identical. These identity
vectors are not a registered FormatProfile; no profile hash is regenerated.

## Confirmation, persistence and recovery

Reuse the existing one-intent conversion entry and conditional confirmation/report;
do not expose recipe or internal source-lane choices. Preview may report affected
Scenes/slots and existing disabled-chroma consequences after complete admission.
Unsupported alpha/unknown fields produce the existing bounded reason and no
partial Project. Preview/cancel creates no Project/journal/CAS acknowledgement.

Keep the exact original ZIP and private source-to-target witnesses with their
lane's existing closed shape and actual profile/slot bindings. Native's existing
witnesses have no sourceSemantics field: derive and check full source semantics
from the verified original/catalog again; do not add a witness field. v1's existing
semantic witness and LociMyu's source/report checks retain their own exact shapes.
Reports reflect the new recipe;
no extra public package fields, borrowed native fallback keys or invented flags.
Original/witness files remain excluded from all five public outputs. Existing
initialization/journal/CAS/readback/publication/recovery fences and captured
identity are unchanged. Source reselect must match original bytes and lane; stale,
different, missing or tampered witnesses cannot publish a partial conversion.
Retry preserves later local edits, original changes and the selected saved recipe.

## Acceptance and stop conditions

Use existing parser/service/file/browser tests rather than another harness:

- Exact new ID vectors and source selection, old recipe/profile/golden identity,
  new current/dormant Scene/slot mapping and each Native receipt lane.
- Source opaque lit/unlit/front/double, source alpha below1 ignored by opaque,
  true/false/absent effective adjustment booleans (including v1 source-double with
  absent side retaining DoubleSide) and distinct family-specific
  disabled-chroma retention. Shared/ambiguous/unknown and MASK/BLEND/active-chroma/
  fractional-opacity rows reject as a whole without writes.
- One connected converted mixed-Mesh browser case for Native, plus representative
  v1/LociMyu service-file continuation using their existing exact-address fixtures:
  edit/scope/reset, independent-profile two returns with local edits, all five
  outputs, Review/Clean, actual selected-generation restore and cold reopen.
- Native9 fresh/cold in all three lanes; interrupted plain GLB uses its retained
  raw original (missing/tampered raw source requires repair), while spatial/Mesh
  keep their existing pre-ack exact-source-reselect recovery;
  receipt/witness tampering, incompatible lane and original mismatch; old retries
  unchanged and no whole-original/GS reads newly introduced.
- Required serial typecheck/full Vitest/four builds, artifact/source-map isolation,
  focused fault regressions and independent final diff review before checkpoint.

Stop only the affected work for an actual contract conflict, new source/alpha/
ownership/capacity interpretation or separately gated adoption/release action.
Physical iOS, offline/PWA, general renderer/storage adoption and publication remain
separate. PO approval of this companion covers the complete three-family unit,
ordinary implementation/testing/fixes and its suitable g0 development checkpoint;
it does not require per-format/helper or small manual-test confirmation.
