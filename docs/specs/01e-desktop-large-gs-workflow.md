### 2.2 ZIP sink aggregation within existing I/O and recovery fences

The restored500k Project cold-opened, but its subsequent backup still exceeded
the unchanged300s download diagnostic. Draw count stayed15; root restore-control
audits increased with output chunks. Keep that failure. Generation write fences
remain before/after each delivered write chunk and around write/close/publication;
do not cache or skip staging/read/write audits to fix this path.

Coalesce only already-checked ZIP output, after the existing per-original-chunk
budget, count and hash transform, before its destination/WorkspaceFS. Assemble
small chunks into owned1MiB blocks. An already-large vendor-owned ZIP chunk
(1–16MiB) retains the existing immediate passthrough path: flush any preceding
partial block, then enqueue that large chunk unchanged. Never clone/retain another
whole16MiB remainder or enqueue a large chunk's many slices. Each transform emits
at most one assembled block, or one partial plus one large chunk; retain only an
owned partial block. Tail publication requires successful size/abort checks.

The original16MiB chunk ceiling and original packageChunks charging still apply
before aggregation. Conservatively allow six extra1MiB slots across assembly,
output/job bridges and generation/OPFS copies; the existing conservative53.75MiB
I/O subtotal plus6MiB remains within the
accepted64MiB shared I/O budget. Source inspection and body hashing stay64KiB;
package bytes, wire/version, checksum, input-before/after, abort/error propagation,
readback and completion receipts remain unchanged. Large passthrough retains
existing ZIP-writer chunk ownership rather than adding an unbounded borrowed input.

Acceptance: byte-identical ordered output for empty/exact/tail/mixed-large inputs,
small buffered inputs owned before suspension, bounded backpressure/queue, original
budget/hash checks charged before grouping, cancellation/write/close/source faults
retain primary errors and no completion receipt. Reuse the five-purpose package
tests and actual restored Project generation-resume→save; keep300s unchanged.
This changes only output partitioning within existing limits, not generation
authority, validation lifetime, recovery policy or a product capacity guarantee.

The approved resident guard reserves at most500,000 source rows and44,500,000
source scalars across new ProjectScene/GSL instances owned by all renderers in one browser document,
including the main workspace, Review and candidate preview. Count each resident
instance even when its source digest is shared. Reserve before starting the one
global SDK decode; a queued native File does not consume a decoded slot. Keep the
reservation through ready, hidden-but-not-released, cancellation and retiring

than temporarily double the budget. This is a conservative work/residency guard,
not a total CPU/GPU memory guarantee or a cross-tab/device-wide allocator.
It does not reinterpret the existing Native/Spark route's accepted limits. Dispose
the old route before mounting the new composition; failed/unproven disposal keeps

do not describe rows, texture counts or the inspector byte budget as total RAM.
The measured1440×900 direct case and actual workspace allocation are observations,
not a promise for arbitrary fullscreen/DPR/device sizes. If a combined view exceeds

## 4. Full-resident Desktop path versus progressive preview

The evaluated first path fully decodes the bounded Desktop source before complete
display. Its first Desktop candidate stage has the explicit§7 exception to
specification01§10's progressive-preview direction. Keep that
direction and iPhone/paging requirements open; do not count this path as G1-A/G1-B.
Use one familiar loading state and cancellation where no durable operation owns
the input. Warm exact retry may retain the captured File. Autonomous cold model
publication still requires the existing prepared marker plus durable originals
and facts; unprepared cold staging retains incomplete-staging-repair. Fresh
initialization retains its own initial receipt/source after all bodies stage.
A CAS body alone never authorizes fact repair or automatic resume.

Alternative: require conservative spatial index, whole-view LOD and bounded page
replacement before enabling larger inputs. Raw ordinal slices only establish
lossless composition; they do not establish safe visibility or whole-view LOD.
New persistent index/derivative profile, incomplete-region policy or alternative
renderer remains a separately concrete design decision. SH3 preview is not chosen.
