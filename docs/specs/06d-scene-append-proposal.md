# 06d — シーンZIPを既存プロジェクトに追加する案

**PROPOSED**。既存の[シーンZIP](05-project-scene-team-workflow.md#73-reviewshare)を
既存プロジェクトへ追加するための製品判断案。現行の閲覧、単独の編集コピー、同じ
プロジェクトの更新受信は、それぞれ現行契約に従う。

## 1. 取り込み時の選択

「ファイルを開く」で選んだシーンZIPは、これまでの閲覧を入口とする。既存プロジェクトに
入れる場合は「既存に追加」を選び、取り込み先とシーン名、モデル・記録・添付の範囲を
確認してから確定する。単独で作業したい場合は既存の「編集コピーを作る」を使う。

最初の対応は、元と取り込み先の物理単位が明示され、1座標単位あたりの長さが一致する
場合とする。プロファイルも同じ対応済みのものに限る。単位不明・不一致やプロファイル差が
あるときは理由を示し、単独で開ける。既存モデルとの自動位置合わせは今回の追加操作に含めない。

## 2. 追加する範囲と既存の記録

- シーンは元の名前と新しいIDで末尾に追加する。既存プロジェクト名・初期シーンと既存の
  モデル、記録、材質は保持する。追加完了後は新しいシーンを画面で開ける。
- ZIPに含まれるモデル・ピン・記録・視点・添付を一組として追加する。同名・同じ素材の
  モデルや記録も別のIDとする。検証済みで同じバイトの素材だけを保管時に共用できる。
- [ProjectFrame](01-domain-rendering.md#21-frames)の向きは共通の規則を使う。
  プロジェクト座標で持つピンと視点は取り込み先の座標系に結び付け、モデル内のピンは
  追加するモデルのローカル座標を保つ。配置、倍率、視点の数値を引き継ぐ。既存モデルとの
  位置合わせが必要な場合は、利用者が別途行う。
- 既存の[シーンから編集用データを作る変換](../../src/projectPackage/reviewSnapshot.ts)を
  対応付けの出発点とする。対応モデルのない記録、未配置のピン、確認が必要なピンの
  区別を保持する。材質の適用範囲と優先関係は保持し、共通材質の対象も新しいIDのモデルに
  限る。開始視点は追加したシーンへ引き継ぐ。
- 元のZIPに含まれる情報だけを取り込む。取り込みの名称で履歴の統合を示さない。

## 3. 確定と中断復旧の設計条件

確定まで書き込みを行わない。確定時に編集ロックを取得し、取り込み先の保存済みの版・座標系、
対象ZIP、表示した内容、追加後の容量と対応形式を再照合する。取り込み先が更新されていれば
確認へ戻る。元のZIPの照合値、取り込み先、追加用のID対応を1回の処理に固定する。
素材の検証・保存後の照合と、現在の作業を公開する境界には既存のSessionとジャーナルを
使う。中断した場合は最後に公開した内容を保持し、復旧を案内する。追加の結果は検証後に
一括で公開する。復旧には同じZIPと同じ処理の記録を使い、再試行や連打は一度の追加に束ねる。
完了後に利用者が同じZIPを選び直して追加を確定した場合は、別のシーンを作る案とする。
開始前は取消を受け付け、開始後は既存の復旧規則に従う。

この案では、保存レシートの具体的な形式、対応のないモデルを含むmap1/map2の採用表、
キャンセル後に持ち越す一時データの扱いは未確定。製品方針を決めた後、データと復旧の仕様を
独立レビューし、確定した仕様に対して実装する。

## 4. 確認項目

- PCとタッチ画面で、閲覧、追加先の確認、取消、追加を通す。
- 同名のモデルや記録があるデータで、既存データと追加データのID、位置、開始視点、
  モデル・添付のハッシュを比較する。元ZIPを単独で開いたときの見え方とも照合する。
- 未対応の単位・形式、容量超過、別タブでの編集中、書き込み開始前の取り込み先変更、
  改変ZIPを拒否し、
  元ファイルと手元の記録を保持する。
- 中断後に別のZIPを拒否し、同じZIPで復旧する。保存・再開を通し、追加シーンが
  1つだけであることを確かめる。
