# 08e シーンごとのモデル配置・差し替え

製品方針と保存・受け渡しの方針は承認済み。下記の接続条件で検証する。

## 利用者の操作と範囲

シーンAでモデルを移動・回転・拡縮しても、シーンBのモデルとピンは移動しない。Aで本体を差し替えた場合、Aでそのモデルに置いたピンだけを要確認にする。補正後もBのピンは元の部位を指す。材質の「このシーンだけ」と「プロジェクト共通」は維持する。

## 保存と受け渡し

- モデルのシーン所属に任意の配置・版の参照を持ち、従来のデータでは元の参照を使う。新しい配置は所属ごとに保存する。現在1シーンだけで使用するモデルも同じ規則を使い、他の端末で別シーンに追加した変更を受け取っても配置を上書きしない。原本は共用する。
- 複数シーンに明示的に追加した同じ記録では、本文と写真の共用を保つ。差し替え後に位置を補正した場合、その所属に新しい位置と対象版を記録する。モデルと座標系が一致することを検査する。未配置の記録、プロジェクト座標のピン、別モデルのピンは影響を受けない。
- シーンの複製・選択出力は、その時点で選択シーンが使う版・材質・座標を含める。画像・モデルの同一原本は一度だけ収録する。新しい本体で旧材質のスロットや旧GSの位置指定面を誤用しない。
- 現行方式を扱えない版で異なる配置のまま再保存することを防ぐ。シーン別配置やピン補正の履歴を含む作業ファイルは、対応版を必要とする。既存ファイルは現状のまま開ける。過去の未完了処理を新しい規則で書き直さない。

map2のモデル所属の任意フィールドを `bindingId`、記録所属の任意フィールドを `anchor` とする。シーン専用操作は `scope: 'scene'` を指定する。元の履歴にこれらのフィールドの書き込みや削除があるときは、後で値が上書きされていても `scene-placement-v1` が必要となる。選択出力では出力する内容から判定する。

## 接続の条件

PC・タッチの2シーンでAを変更し、Bの配置・ピン・視点・材質が不変であることを確認する。Aの要確認ピンを補正し、共用した本文・写真とBの座標を照合する。保存・再開、選択出力、別環境での追加・返送、両端末で異なるシーンを変更した場合と同一シーンの競合、書き込み中断・再試行を含める。旧版が履歴を誤読する状態で新しい書き込みを有効にしない。
