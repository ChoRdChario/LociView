# 08b: 共有する変更に任意の編集者名を残す方針

Status: **PROPOSED —未承認・未実装**。08aの次候補となる利用者向け方針。
現在の実装・検証は[todo](../../tasks/todo.md)が正本。この案は保存schemaやprofileを
批准せず、その設計・独立レビュー・必要な承認の前提となる共有範囲の判断をまとめる。
製品方針としての独立レビュー2026-10-29はPASS。保存設計・runtimeの承認や検証ではない。

## 解決すること

更新の受信や競合候補の確認で、どの編集者名を付けた変更か分かるようにする。
最初の範囲は、今後この端末で確定する編集への任意の自己申告名と、既存のCaption変更・
競合候補の補助表示。ログイン、本人確認、端末や人の同一性判定、汎用履歴画面は追加しない。
名前や時刻で競合の勝者を決めない。

## 推奨する利用者向け方針

- Projectの設定で名前を任意入力し、「このプロジェクトの今後の編集にこの名前を残す」を明示的に有効化する。
  初期状態は無効。既存のブラウザ内表示名は入力の初期値にだけ使い、黙って共有へ転用しない。
- 有効化後に確定したローカル編集へ、その時点の名前を保存する。名前変更・停止は今後の
  編集へ適用する。過去の元changeや受信した相手の情報を書き換えない。
  名前は操作確定時に捕捉して固定し、再試行中に設定が変わっても元の操作へ付け直さない。
- 過去の未記録変更は「編集者情報なし」と表示する。Automerge actor IDや変更内容から
  過去の人物を推測しない。同名でも同一人物と扱わず、自己申告の表示名として説明する。
- 保存に失敗した編集を名前だけ記録せず、既存の確定・再試行・中断復旧と同じ結果にする。
  新しいlocal transaction IDと同じ元changeに申告を関連付ける設計を検討する。
  change hashの自己参照やactorの固定化を前提にしない。

## ファイルへの含め方

[仕様02 §9.4](02-storage-package-migration.md)の共同作業時の開示と、
Review／Cleanの情報除外を具体化する。既存の原本保持・完全履歴・差分の規則は保つ。

| ファイル | この案での編集者情報 |
|---|---|
| 作業一式（Workspace） | 実際の元履歴とともに保持し、含まれることを出力前に表示 |
| 変更分（Contribution） | 実際の差分に含まれる情報を保持し、含まれることを出力前に表示 |
| バックアップ | 同じ履歴へ正確に復元するため保持。復元後も勝手に名前を追加しない |
| 閲覧用シーン（Review） | 専用snapshotから除外 |
| 独立コピー（Clean） | 元の編集者情報を除外し、新しい履歴として開始。以後の名前記録は別に明示設定 |

本文に手入力された氏名や、画像・音声に含まれる情報まで匿名化する機能ではない。
名前の記録停止やClean作成で、既に相手へ渡った履歴を削除したとは説明しない。

## 承認後に必要な設計と検証

正確な保存位置、schema／semantic profile、旧読取側の扱い、検証・snapshot allowlistは
未決定。共有する永続情報の方針をPOが選んだ後、その範囲の保存設計を具体化して独立レビュー
する。大きな互換性判断をこの製品方針だけで承認済みとせず、必要な判断は具体案として提示する。
既存actor生成・元change bytes・未知候補保持・Sessionの確定／公開／復旧境界は変更しない。

受入れは、明示設定→将来の編集→受信・競合候補表示→全5purpose→中断復旧・cold再開。
未記録の旧変更、記録停止、名前変更、相手の記録、Review／Cleanへの情報漏れ、失敗後の
exact retryを確認する。依存追加や外部送信サービスは不要。承認前には実装しない。
